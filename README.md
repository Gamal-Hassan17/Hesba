# حِسبة — كل جنيه بحساب

تطبيق ويب عربي لإدارة عدة بنود مالية، وتسجيل المصروفات والإيداعات لكل بند بشكل مستقل.

## المتطلبات
- Python 3.10 أو أحدث
- pip

## التشغيل على Windows

افتح Terminal داخل فولدر المشروع ثم نفّذ:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

عدّل ملف `.env` وضع قيمة عشوائية قوية لـ `SECRET_KEY` وكلمة مرور قوية. لا ترفع ملف `.env` إلى GitHub.

أنشئ حساب المدير:

```powershell
$env:FLASK_APP = "app.py"
flask create-admin
```

ثم شغّل التطبيق:

```powershell
flask run
```

افتح `http://127.0.0.1:5000` في المتصفح.

## التشغيل على Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
export FLASK_APP=app.py
flask create-admin
flask run
```

## قاعدة البيانات والنشر على Render

يستخدم التطبيق SQLite محليًا افتراضيًا داخل `instance/`. عند النشر لا تعتمد على SQLite في نظام ملفات مؤقت؛ استخدم PostgreSQL، وسيحوّل التطبيق تلقائيًا روابط `postgres://` و`postgresql://` إلى صيغة psycopg 3.

1. أنشئ قاعدة PostgreSQL في Supabase أو Render.
2. انسخ رابط الاتصال المناسب للاستضافة وضعه في متغير البيئة `DATABASE_URL` (لا تضعه داخل الكود).
3. ارفع المستودع إلى GitHub ثم أنشئ Web Service على Render من المستودع.
4. استخدم أمر البناء `pip install -r requirements.txt` وأمر التشغيل `gunicorn app:app`.
5. اضبط `SECRET_KEY` بقيمة عشوائية طويلة، و`COOKIE_SECURE=1`، و`FLASK_DEBUG=0`.
6. بعد أول نشر، أنشئ حساب المدير من Render Shell بالأمر `flask --app app.py create-admin`.

يوجد ملف `render.yaml` لتوضيح إعدادات الخدمة. متغير `DATABASE_URL` يُضاف يدويًا من لوحة Render، ولا تحفظ أسرار الاتصال في GitHub.

## تخزين إيصالات المصروفات في Supabase Storage

في Supabase افتح Storage وأنشئ Bucket باسم `receipts` واجعله **Private**. ثم أضف إلى Environment Variables في Render:

- `SUPABASE_URL`: عنوان مشروع Supabase.
- `SUPABASE_SERVICE_ROLE_KEY`: مفتاح الخدمة السري من إعدادات API. لا تضعه في الواجهة الأمامية أو GitHub.
- `SUPABASE_BUCKET`: `receipts`.

عند وجود إعدادات Supabase مكتملة، تُرفع الإيصالات إليه، ويُنشئ التطبيق رابط عرض موقّعًا قصير الصلاحية بعد التحقق من تسجيل الدخول. عند عدم ضبط Supabase يعمل التخزين المحلي للتطوير فقط. الإيصالات القديمة المحفوظة محليًا لا تنتقل تلقائيًا إلى Supabase؛ انقلها قبل حذف ملفاتها المحلية.

## إعدادات الإنتاج والأمان

- عيّن `SECRET_KEY` قويًا عبر متغيرات البيئة.
- استخدم HTTPS و`COOKIE_SECURE=1`.
- لا ترفع `.env` أو ملف قاعدة البيانات أو مفاتيح Supabase إلى GitHub.
- شغّل التطبيق بخادم WSGI مثل Gunicorn، وليس بخادم التطوير.
- فعّل النسخ الاحتياطي التلقائي لقاعدة PostgreSQL من مزود قاعدة البيانات، واختبر الاستعادة دوريًا. نسخ Excel من داخل التطبيق تظل نسخة تصدير يدوية وليست بديلًا عن نسخ قاعدة البيانات.

## المميزات الحالية

- تسجيل دخول خاص.
- إنشاء بنود مالية مستقلة.
- إضافة مصروفات وإيداعات.
- حساب إجمالي الأموال والمصروفات والرصيد تلقائيًا.
- جدول مصروفات مع بحث وتصفية وترتيب.
- تعديل وحذف المصروفات.
- أرشفة البنود مع الاحتفاظ بالسجل.
- واجهة عربية RTL متجاوبة مع الهاتف.
- حماية CSRF للنماذج.

## ملاحظات

هذا إصدار أولي قابل للتطوير. قبل الاعتماد عليه في مبالغ كبيرة، اختبر النسخ الاحتياطي والاستعادة وتأمين الاستضافة. التواريخ تُحفظ حاليًا كتوقيت محلي للتطبيق؛ عند النشر على عدة مناطق زمنية، يُفضّل توحيد التخزين على UTC وتحديد المنطقة الزمنية للعرض.


## نوعا البنود المالية
- **بميزانية محددة:** أدخل المبلغ الأولي، ويمكن إضافة مبالغ لاحقًا، وسيظهر الرصيد المتبقي.
- **مصروفات فقط بدون ميزانية:** لا يلزم إدخال مبلغ عند إنشاء البند؛ سجّل مصروفات مثل توظيب الشقة، وسيحسب النظام إجمالي المصروفات وعددها دون إظهار رصيد متبقٍ أو زر إضافة أموال.

عند تشغيل النسخة الجديدة على قاعدة بيانات سابقة، يضيف التطبيق عمود `is_budgeted` تلقائيًا مع الاحتفاظ بالبيانات الحالية.


## النسخ الاحتياطي إلى Excel (الإصدار 3)
- **حفظ نسخة Excel** ينشئ نسخة جديدة من البيانات الحالية، ولا يحتاج إلى ملف سابق.
- **تحديث ملف Excel** يدمج السجلات الحالية في الملف الموجود باستخدام أرقام السجلات، ويحافظ على السجلات التاريخية الموجودة في Excel فقط.
- ورقة `البنود_المالية` تعرض الميزانية الأولية وإجمالي الأموال المضافة والمصروفات والرصيد المتبقي، وتعرض ورقة `تفاصيل_المصروفات` كل مصروف في صف مستقل، وورقة `تفاصيل_الأموال_المضافة` كل عملية إضافة في صف مستقل، وورقة `المصروفات_المتكررة` قواعد التكرار.
- عند تحديث ملفات النسخ الاحتياطي القديمة المدعومة، تُحوَّل أسماء الأوراق والأعمدة الظاهرة إلى العربية مع الحفاظ على السجلات الموجودة.
- المتصفحات التي تدعم الوصول إلى الملفات يمكنها تحديث الملف المختار مباشرة. المتصفحات الأخرى تنزّل نسخة محدثة؛ استبدل الملف القديم بالنسخة التي تم تنزيلها يدويًا.


## مميزات حِسبة الإضافية

- **المصروفات المتكررة:** قواعد أسبوعية وشهرية وسنوية مع موعد استحقاق قادم وإيقاف/تفعيل القاعدة. تُنشأ المصروفات المستحقة عند فتح التطبيق.
- **التقارير والتحليلات:** ملخص حسب الفترة، مقارنة بالفترة السابقة، وتوزيع المصروفات حسب البند.
- **إيصالات المصروفات:** إرفاق صور JPG/PNG/WEBP أو PDF بحد أقصى 5 ميجابايت؛ تحفظ محليًا أثناء التطوير، أو في Supabase Storage الخاص عند ضبط متغيراته.
- **نسخ Excel بالعربية:** أسماء أوراق وأعمدة عربية مع الاحتفاظ بالتوافق مع النسخ الأقدم المدعومة.
